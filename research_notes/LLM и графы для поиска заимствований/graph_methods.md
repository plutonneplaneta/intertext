# Graph-based and GNN approaches to detecting textual borrowing, allusion, and reuse between two corpora

## Key Question 1: Beyond counting shared single dependency edges, what graph-based methods exist for scoring structural/syntactic similarity between two short text spans (GED, MCS, graph/tree kernels, GNN encoders)? Which are known to be more discriminative than raw shared-edge counts, and why?

### Takeaway
A range of graph-based similarity measures exist beyond raw shared-edge counting — graph edit distance (GED), maximum common (connected) subgraph (MCS), and graph/tree kernels (Weisfeiler-Lehman, subtree, walk-based) — and all of them are more discriminative than naive shared-edge counts because they score the *configuration* of shared structure (its size, connectivity, or global-vs-local pattern) rather than treating every matching edge as independent evidence; this directly targets the failure mode the pilot observed, where "almost any two Russian sentences share some generic syntactic edge."

### Cited Findings
- Graph edit distance (GED) between dependency graphs has been applied directly to plagiarism detection: sentences are represented as dependency graphs (words linked by grammatical relations), and GED — the minimum-cost sequence of node/edge insertions, deletions, substitutions needed to transform one graph into the other — is used as the distance metric; a key stated advantage of the graph representation over bag-of-words/n-gram methods is that it captures structural similarity while being indifferent to word order and can capture similarity between different words that play the same structural role — [Graph-based NLP: GED applied to plagiarism detection (CORE)](https://core.ac.uk/outputs/646199500/)
- GED is formally defined as the minimum number of edit operations (node/edge insertion, deletion, substitution, merging/splitting) needed to morph one graph into another, and has been used to approximate similarity between program dependency graphs (PDGs) via recursive greedy algorithms when exact computation is intractable — [Graph edit distance in code plagiarism / PDG comparison](https://arxiv.org/pdf/2102.03997)
- Maximum common subgraph (MCS): a text-as-graph method (terms as nodes, term-adjacency as edges) computes similarity as the sum of a "node similarity" term and an "edge similarity" term derived from the MCS of the two text graphs; MCS-based similarity does not require a hand-designed edit-cost function (unlike GED), which is a stated advantage, but computing the MCS is itself NP-hard — [A Graph-Based Text Similarity Algorithm](https://www.atlantis-press.com/proceedings/citcs-12/3181); [Maximum Common Subelement Metrics](https://arxiv.org/pdf/1501.06774)
- Weisfeiler-Lehman (WL) graph kernels build a similarity/feature representation via iterative "color refinement" — each node's label is repeatedly updated by hashing together its own label and its neighbors' labels, and the kernel value is computed from the resulting multiset of labels/subtree patterns across iterations; this is described as "a central paradigm in graph learning," broadly used as a graph similarity measure in kernel machine learning because it efficiently captures both local and increasingly-global (multi-hop) structural patterns, not just single edges — [Weisfeiler-Lehman Kernel Overview](https://www.emergentmind.com/topics/weisfeiler-lehman-kernel); [Weisfeiler-Lehman Graph Kernels (Shervashidze et al., JMLR)](https://www.jmlr.org/papers/volume12/shervashidze11a/shervashidze11a.pdf)
- Standard WL kernels are limited because they compare labels/subtree-unfoldings by strict equality, which the authors call "arguably too restrictive." A generalized WL kernel instead computes similarity between the unfolded subtrees using a specifically-fitted variant of tree edit distance (efficiently computable) and/or a Wasserstein distance between vector representations of WL labels, giving a "more natural and finer-grained" similarity than exact-match WL — [A Generalized Weisfeiler-Lehman Graph Kernel](https://arxiv.org/abs/2101.08104)
- Tree/walk kernels for paraphrase and plagiarism detection: tree kernels extended to operate over *pairs* of parse/dependency trees count common sub-structures (subtrees, or "walks"/paths of various lengths) as the similarity signal; because paraphrase is characterized by syntactic/semantic patterns rather than exact lexical match, a kernel machine can automatically learn which shared sub-structures are diagnostic from training data, rather than treating all shared edges equally. A walk-based, semantically-enriched tree kernel over dependency trees ("Vector Tree Kernel," VTK) that combines path-based structural matching with distributed word representations achieved 0.72 accuracy on the MSR Paraphrase Corpus — [Tree kernel / VTK for paraphrase detection](https://lacuna.tiptreesystems.com/work/a-walk-based-semantically-enriched-tree-kernel-over-distributed-word/wrk_246f105d33082d80c0dc39b5fe353379); source-code analogs: [WASTK weighted AST kernel for plagiarism](https://www.researchgate.net/publication/311912240_WASTK_An_Weighted_Abstract_Syntax_Tree_Kernel_Method_for_Source_Code_Plagiarism_Detection); [Parse-tree-kernel plagiarism detection](https://www.researchgate.net/publication/273413628_An_application_for_plagiarized_source_code_detection_based_on_a_parse_tree_kernel)
- On why GNN-learned embeddings can outdo raw structural/count features for discriminating genuine vs. superficial structural similarity: in a 2025-26 study distinguishing human citation graphs from LLM-fabricated ones, a classifier using only graph-structural features (degree/closeness/eigenvector centrality, clustering coefficient) reached only 60.8% accuracy (near chance) at telling human from GPT-4o-generated reference graphs, because the *topology* of fabricated graphs closely mimics real ones. Adding semantic (embedding) node features raised a Random Forest to 83.5%, and a GNN that combined graph structure with embedding-based node features reached 93% accuracy — i.e., structure alone was "insufficient" but became highly discriminative once fused with content/semantic signal via message passing — [Structurally Human, Semantically Biased: Detecting LLM-Generated References with Embeddings and GNNs](https://arxiv.org/html/2601.20704)

### Inferences
- The pilot's finding — that shared dependency edges alone have high recall (33%) but terrible ranking (median rank ~200-270) — is consistent with the general pattern in the literature: raw structural overlap (single shared edges, or topology-only graph features) is necessary-but-not-sufficient and saturates quickly, because generic syntactic/topological patterns recur constantly across unrelated text/graph pairs. Every method more discriminative than raw-edge-counting in the findings above adds one of two things: (a) a notion of *connected/global configuration* (GED cost of the whole alignment, size of the maximum *connected* common subgraph, or WL's multi-hop neighborhood hashing) rather than a flat inventory of edges, or (b) fusion with a *non-structural* signal (lexical identity via labels, semantic embeddings, or learned continuous features) at the node level before or during graph comparison. This suggests the most promising direction for the target project is not "a better graph kernel in isolation" but a graph kernel/GNN whose node/edge labels are informative (lemma + rarity weight, not just POS/relation type) and whose scoring rewards *connected multi-edge* matches over scattered single-edge coincidences — i.e., moving from "shared edge count" toward "size of maximum common connected subgraph" or "WL similarity with rarity-weighted labels" is a concrete, implementable next step using the existing dependency-parse infrastructure.
- Because MCS and generalized-WL kernels are non-parametric (no training required beyond kernel hyperparameters), they are directly usable as a fourth signal to combine with the existing three (lemma n-gram, embedding cosine, logistic regression) without needing a large labeled set — only the ~46 labeled paragraphs already available for weight-fitting in the existing LOTO-CV logistic regression.

### Gaps
- No source found gives a head-to-head, apples-to-apples comparison of GED vs. MCS vs. WL-kernel vs. shared-edge-count specifically on *short, few-word dependency (sub)graphs of the kind produced by a single Biblical verse or novel sentence* (as opposed to full documents or molecules/chemical graphs, where most GED/MCS benchmarking has occurred). The claim that these methods are "more discriminative" is well-supported at the general graph-similarity level but not verified quantitatively for this exact short-span, cross-register regime; this would need to be validated empirically on the project's own annotated set.
- Runtime/complexity feasibility on modest hardware: GED and MCS are both NP-hard in general; for short dependency graphs (a handful to ~30 nodes per verse/sentence) this is very likely tractable with exact or near-exact solvers, but no source quantified per-pair runtime at this scale, so this should be treated as a low-risk assumption to be confirmed rather than a proven fact.

## Key Question 2: Can a GNN realistically be trained/fine-tuned to score (source, target) pairs with only ~16-30 confirmed positive pairs? What few-shot, self-supervised, contrastive, or transfer-learning strategies apply?

### Takeaway
Training a GNN pair-scorer from scratch on ~16-30 positive pairs is not realistic on its own, but the graph-learning literature offers a well-established recipe for exactly this label regime — self-supervised/contrastive pretraining of a graph encoder on the (unlabeled) pool of candidate pairs, followed by a lightweight supervised head trained on the few dozen labels, in a Siamese/twin architecture — and this pattern is explicitly documented as reducing the "supervised learning burden," with the largest benefit precisely when labeled data is scarce.

### Cited Findings
- Siamese networks pair two identical (weight-sharing) branches with a similarity function (energy function, e.g. cosine or Euclidean distance) trained via contrastive or triplet loss to pull matched pairs together and push unmatched pairs apart; this architecture is described as one of the most common "metric-based" learners for one-shot/few-shot verification and retrieval tasks, and generalizes to a GNN branch when inputs are graphs — [Siamese Networks overview](https://www.emergentmind.com/topics/siamese-networks); [Siamese Neural Network — ScienceDirect Topics](https://www.sciencedirect.com/topics/computer-science/siamese-neural-network)
- Graph Contrastive Coding (GCC) pretrains a GNN encoder with a purely self-supervised contrastive pretext task on subgraphs (contrasting augmented views of the same subgraph — via node/edge dropping and masking — against other subgraphs in a batch, with no labels needed at all), and the paper demonstrates that this pretraining "requires substantially fewer labeled examples for downstream tasks compared to training from scratch," with gains "most pronounced when downstream labeled data is limited"; the recommended transfer recipe is: (1) initialize with pretrained weights, (2) fine-tune on the target task with the available (small) labeled set, (3) use conservative learning rates to avoid destroying the pretrained representation — [GCC: Graph Contrastive Coding for GNN Pre-Training](https://arxiv.org/pdf/2006.09963)
- More generally, GNN transfer-learning frameworks distinguish "freezing mode" (pretrained encoder is a fixed feature extractor; only a small classifier/head is trained on top) from "full fine-tuning mode." A frozen ("direct-transferring") encoder is stated to make downstream training 10-30x faster since no gradients are computed for the encoder, and frozen encoders are specifically noted to "prevent overfitting in small datasets by reusing robust pre-trained features" and to give "stronger out-of-distribution performance" — directly relevant to a ~16-30-positive-pair regime where a from-scratch GNN would almost certainly overfit — [Frozen encoders in GNN transfer learning](https://medium.com/@utsavsharma1990/frozen-encoders-foundations-applications-and-advanced-techniques-5b17688dd09a); related formal treatment: [Transfer Learning of GNNs with Ego-Graph Information Maximization (EGI), NeurIPS 2021](https://proceedings.neurips.cc/paper_files/paper/2021/file/0dd6049f5fa537d41753be6d37859430-Paper.pdf)
- Graph contrastive learning under scarce labels is an active, separate line of work: methods addressing "insufficient supervisory signals" and "scarcity of positive samples" in few-shot semi-supervised graph settings include confidence-propagation-based semi-supervised contrastive learning (SGCL) and augmentation-free edge contrastive learning (AFECL), the latter reporting state-of-the-art performance specifically on link prediction and node classification "of extremely scarce labels" — [SGCL: Semi-supervised Graph Contrastive Learning](https://www.sciencedirect.com/science/article/abs/pii/S0950705124009055); [Edge Contrastive Learning (AFECL)](https://arxiv.org/html/2412.11075v1)
- Meta-learning approaches for graphs fall into two families: gradient-based methods (learn an initialization that adapts in a few gradient steps to a new task, e.g. MAML-style) and metric-based methods (learn a generalized distance/matching function from many small "episodes," e.g. Meta-GNN, Edge-labeling GNN). A concrete pair-scoring instance in exactly this style is TGLink, which "samples K labeled [gene] pair samples to form a support set" and Q pairs to form a query set for few-shot link/pair inference on biological networks — architecturally the same shape as scoring (source, target) textual pairs with only a couple dozen labels — [Meta-learning with GNNs: methods and applications](https://arxiv.org/pdf/2103.00137); [Structure-enhanced graph meta-learning (TGLink)](https://genomebiology.biomedcentral.com/articles/10.1186/s13059-025-03860-8); [Edge-labeling GNN for Few-shot Learning](https://arxiv.org/pdf/1905.01436); [Meta-GNN: Few-shot Node Classification](https://arxiv.org/abs/1905.09718)

### Inferences
- The literature converges on a two-stage recipe that is directly executable with the project's existing assets and RTX 3060 budget: (1) self-supervised/contrastive pretraining of a small dependency-graph GNN encoder using the *unlabeled* pool of candidate (target-paragraph, Bible-verse) pairs already produced by the existing wide-net retrieval stage (thousands of candidates per target paragraph, all unlabeled) — e.g., contrasting a graph against augmented (edge-dropped/masked) versions of itself, or against paired positive/negative candidate graphs using known-negative sampling from clearly-unrelated verses — followed by (2) a lightweight Siamese scoring head (a small MLP over the two graph embeddings, or their difference/cosine) trained/calibrated on the ~16-30 confirmed positive pairs (plus engineered negatives) via leave-one-out or leave-one-target-out cross-validation, matching the evaluation protocol already used for the three-signal logistic regression. This keeps the number of trained parameters small enough to avoid overfitting on dozens of labels, consistent with the frozen/lightweight-head guidance above.
- Given the extreme label scarcity (fewer positives than a typical few-shot "N-way K-shot" episode count), metric-based meta-learning (Siamese/matching-network style) is more appropriate than gradient-based meta-learning (MAML-style), which typically needs many small labeled tasks to meta-train across — a resource the project does not have (there is only one "task": scoring citation pairs in one novel against one Bible). This favors the GCC/Siamese-contrastive-pretraining route over formal meta-learning.

### Gaps
- No source specifically demonstrates this recipe (contrastive dependency-graph pretraining + Siamese head) applied to *textual reuse/allusion* detection at this label scale; all cited contrastive/meta-learning evidence comes from generic graph-ML benchmarks (citation networks, molecules, gene regulatory networks) or generic few-shot image/text settings, so the transfer to short syntactic dependency (sub)graphs of sentences is an extrapolation, not a directly documented result — flagged as an inference above, not a cited fact.
- No quantitative floor was found for "how few labeled pairs is too few" for the fine-tuning stage specifically; the ~16-30 positive count is within the range typically called "few-shot" in the meta-learning literature (K-shot with K in single-to-low-double digits), but none of the fetched sources gave a numeric minimum below which even a frozen-encoder + linear head fails.

## Key Question 3: Is there prior work modeling a whole source and target corpus as ONE heterogeneous graph and using link prediction, rather than scoring pairs independently? How does this compare to pairwise scoring for citation/plagiarism tasks?

### Takeaway
Yes — heterogeneous-graph link prediction for citation-type tasks is an established and actively developed approach (legal case-law citation, multi-intent scientific citation prediction), and in the one case with a direct, controlled comparison, joint/graph-based link prediction over an enriched heterogeneous citation graph outperformed a plain (non-enriched) GNN baseline by a clear margin — but no source directly compared a whole-corpus heterogeneous-graph link-prediction formulation against independent pairwise scoring on the *same* task and dataset, so the size of that specific advantage remains unconfirmed.

### Cited Findings
- "The Missing Link: Joint Legal Citation Prediction Using Heterogeneous Graph Enrichment" builds a heterogeneous graph with Case and Law node types and Case-Case / Case-Law citation edge types, enriches it with categorical "meta-feature" nodes (court type, law code, jurisdiction) connected to case/law nodes, and predicts citation links using a modified relational graph convolutional network (RGCN) with an added general residual connection (rather than only a self-loop) plus an asymmetric inner-product decoder for link scoring; initial node features come from BERT-based sentence embeddings of the full legal documents. Joint learning of both citation types at once, on the enriched graph, improved case-case link prediction (average precision) by up to 7.2 points over a plain RGCN baseline on one dataset (87.5% vs 80.3% AP on "OLD36k") and by 2.2 points on a larger dataset (88.1% vs 85.9% AP on "OLD201k", 201,823 cases / 50,814 laws / ~90k case-case edges), while also being nearly 2x more training-efficient than training separate per-relation models — [The Missing Link: Joint Legal Citation Prediction using Heterogeneous Graph Enrichment](https://arxiv.org/html/2506.22165v1)
- A separate line of work, Heterogeneous Graph Fusion Network (HGFN), predicts multi-intent scientific citations by fusing the textual representation of a citation sentence with the representation of a heterogeneous subgraph built around that citation, feeding the fusion into a classifier — again treating citation prediction as graph-structured rather than purely pairwise text-matching — [Multi-intent prediction via heterogeneous graph fusion network](https://link.springer.com/article/10.1007/s11192-025-05493-x)
- General link-prediction-on-heterogeneous-graphs research notes this framing is used across many domains (drug-drug/drug-target interaction, venture-capital investment forecasting, e-commerce click-through prediction) and that a harder variant — link prediction on graphs whose node/edge types are *latent* rather than observed ("latent heterogeneous graphs," LHG) — has recently been studied, which could matter here since "verse" and "novel paragraph" would be two clearly observed node types but the relation type (echo, quote, structural paraphrase) is itself latent — [Link Prediction on Latent Heterogeneous Graphs](https://arxiv.org/abs/2302.10432)

### Inferences
- The legal-citation results are the clearest available evidence that folding a citation-detection task into a single graph with link prediction, rather than scoring source/target pairs independently, buys real accuracy (2-7 AP points) — but that gain came from *enrichment with additional relational context* (jurisdiction/court/law-code meta-nodes, and joint multi-relation training) rather than from graph-based link prediction being intrinsically superior to pairwise scoring per se. This suggests the analogous move for the Bible-citation project would be to enrich a verse/paragraph graph with auxiliary structural nodes it does not yet have — e.g., book/chapter nodes, shared-lemma nodes, or shared-construction ("recurring liturgical phrase") nodes bridging many verses and many paragraphs at once — rather than assuming that switching from pairwise LR-combination to link prediction alone would replicate the legal-domain gains.
- A whole-corpus heterogeneous graph could also be a natural way to inject the already-computed shared-lemma and shared-dependency-edge signals as first-class *edge types* (verse-shares-lemma-with-paragraph, verse-shares-dependency-pattern-with-paragraph) feeding into a single RGCN/HGT-style link predictor, essentially generalizing the existing three-feature logistic regression into a graph model; this is consistent with the project's own finding that logistic regression already fuses several relational signals, so a heterograph would formalize (not replace) that fusion.

### Gaps
- No source was found running a like-for-like ablation of "graph-wide link prediction" vs. "independent pairwise classifier over the same features" on a citation or plagiarism task — the comparisons found are graph-enriched vs. non-enriched graph models, not graph vs. non-graph. The claimed advantage of the whole-corpus-graph framing over pairwise scoring is therefore not directly quantified in the literature reviewed, and should be treated as a promising but empirically unverified hypothesis for this project.
- No prior work was found applying whole-corpus heterogeneous-graph link prediction specifically to intertextual allusion/citation detection between a literary corpus and a scriptural corpus (as opposed to legal or scientific citation networks); this is a genuine gap, not merely an unindexed result — the closest analogs found are domain citation networks with much larger label counts (tens of thousands of edges) than the ~16-30 available here, which is a scale mismatch worth flagging explicitly (see Key Question 2/6 discussion of label scarcity).

## Key Question 4: Are there graph-based or graph-neural methods specifically documented for cross-lingual or cross-register textual reuse detection (e.g., a modern paraphrase of an older/liturgical-register source)?

### Takeaway
Cross-lingual/cross-register textual-reuse detection is an active research area, but the documented state of the art is overwhelmingly embedding-based (multilingual sentence transformers), not graph-based; the one clearly graph-based method found — a "graph transformer for cross-lingual plagiarism detection" — could not be fully verified due to access restrictions, so its details should be treated as a lead to follow up rather than a confirmed finding, and this is itself a notable gap given how directly it matches the project's Church-Slavonic-to-modern-Russian register-shift problem.

### Cited Findings
- Cross-lingual paraphrase/text-reuse detection is described as a fast-growing subfield (e.g., English-Urdu sentence-level cross-lingual paraphrase detection, cross-lingual text alignment for fine-grained plagiarism detection), and multiple sources note that "paraphrased and especially the cross-lingual cases of reuse are much harder to detect" than literal copy-paste reuse — [Sentential Cross-lingual Paraphrase Detection for English-Urdu](https://journals.sagepub.com/doi/10.1177/30504554251319446); [Cross-lingual text alignment for fine-grained plagiarism detection](https://journals.sagepub.com/doi/10.1177/0165551518787696)
- A "Graph Transformer for cross-lingual plagiarism detection" is indexed on ResearchGate, described in search results as representing text passages in different languages via knowledge graphs and using a graph-transformer architecture (multi-head attention enabling direct node-to-node relations regardless of graph distance) rather than sequential-position-based encoding — [Graph transformer for cross-lingual plagiarism detection](https://www.researchgate.net/publication/363187981_Graph_transformer_for_cross-lingual_plagiarism_detection) — **note: full text was not accessible (HTTP 403); architecture/results summarized here come only from search-result snippets, not verified against the paper itself.**
- For the specific liturgical/scriptural cross-register case: SPhilBERTa, a trilingual Sentence-RoBERTa model for classical philology, was purpose-built to detect intertextual parallels across Ancient Greek, Latin, and English by training on automatically back-translated data, and is presented as enabling "automated detection of intertextual parallels" across these registers/languages — this is an embedding, not graph-based, solution — [Graecia capta... Detecting Latin Allusions to Ancient Greek Literature](https://arxiv.org/abs/2308.12008)
- A closely analogous project to the target project's problem — detecting Biblical (Psalmic) reuse within a different-register/different-era corpus (the New Testament) — exists ("Detection and Typology of Psalmic Text Reuses in the New Testament," Religions 2026) using traditional NLP similarity measures (tokenization, lemmatization, POS-tagging, stop-word filtering, synset assignment), but full methodological detail could not be retrieved (access blocked) — [Detection and Typology of Psalmic Text Reuses in the New Testament](https://doi.org/10.3390/rel17010088) — **flagged as an access gap, not a confirmed finding of method.**
- A directly relevant finding on translation and register effects: a study using multilingual embedding spaces on Biblical texts found that human translators "amplify certain literary characteristics" (rhetorical/intertextual devices) relative to a neutral machine-translation baseline — implying that intertextual signal strength is not stable across registers/translations and can be deliberately heightened or flattened by the transformation between source and target register, a confound relevant to a project whose target text paraphrases Church-Slavonic-inflected language into a 19th-century literary register — [Characterizing the Effects of Translation on Intertextuality using Multilingual Embedding Spaces](https://arxiv.org/pdf/2501.10731) (no graph methods used, confirmed by explicit absence in the abstract/methodology)
- MiqraBERT (2025-26) fine-tunes a Sentence-BERT model specifically via regression for Biblical Hebrew parallel-passage detection, another embedding-only (non-graph) cross-register-adjacent approach — [MiqraBERT: Regression-Based Sentence-BERT Finetuning for Biblical Hebrew Parallel Detection](https://arxiv.org/pdf/2606.19638) (title/topic only; full content not fetched)

### Inferences
- The near-total absence of graph-based methods in the cross-lingual/cross-register text-reuse literature (versus the abundance of embedding-based methods) is itself informative: it suggests dependency-graph structure is comparatively brittle across the specific register shift in this project (paraphrase of Church-Slavonic-inflected biblical language into 19th-century literary Russian), because parse structure, word order, and even part-of-speech distributions can differ substantially between liturgical/archaic registers and modern prose, more so than lexical/semantic content does. This is a plausible explanation (not confirmed by any source) for why the project's own dependency-edge signal, despite highest recall, has such poor ranking discriminativeness — cross-register paraphrase may preserve *meaning* far more reliably than it preserves *syntactic configuration*, which would argue for treating any dependency-graph signal as a recall booster rather than a primary ranking feature, and for prioritizing semantic/embedding signals (or, per Key Question 1, graph kernels operating over *semantically labeled* rather than purely syntactic nodes) for final ranking in this cross-register setting specifically.

### Gaps
- The one directly graph-based cross-lingual plagiarism method found (graph transformer) could not be accessed in full (403 error on ResearchGate); its training-data requirements, exact graph construction procedure, and whether it needs large labeled datasets are unknown and should be treated as an open question, not a source of a validated technique.
- No source was found addressing graph-based methods specifically for the archaic/liturgical-to-modern register shift (as opposed to cross-*lingual* shift, which is what nearly every "cross-lingual reuse detection" paper actually studies); the project's use case — a single language, but a sharp diachronic/register shift — is a narrower and less-studied problem than cross-lingual detection, and this literature should be read as adjacent, not identical, to the project's needs.

## Key Question 5: Is stemmatology / computational textual criticism a relevant methodological neighbor here, and does it offer transferable graph-construction or scoring techniques?

### Takeaway
Stemmatology is a genuine methodological neighbor in that it also builds graph/tree structures from many-to-many textual variant relationships and has decades of tooling for this, but its core techniques (Bayesian phylogenetic tree inference over collated *variant readings* between full manuscript witnesses of the *same* underlying text) are built for a different problem — reconstructing a hypothesized genealogical tree among near-identical copies — and no source found discusses applying these specific tools to allusion/citation detection between two genuinely different, independently-composed texts.

### Cited Findings
- Stemmatology is defined as the study of textual traditions using genealogical methods applied to sets of copies of a text whose original ("autograph") has been lost; it has drawn on phylogenetics since the 1950s and continues to do so, including "cladistic analysis" (e.g., the Canterbury Tales project's use of the PAUP phylogenetics software) — [Handbook of Stemmatology](https://www.academia.edu/44924958/Handbook_of_Stemmatology_History_Methodology_Digital_Approaches); [Stemmatology: an R package for computer-assisted analysis of textual traditions](https://www.academia.edu/36001397/Stemmatology_an_R_package_for_the_computer_assisted_analysis_of_textual_traditions_paper_)
- A concrete modern pipeline: manuscript variant collations encoded in TEI XML are mapped (via the `teiphy` Python package) into BEAST 2, a Bayesian Evolutionary Analysis by Sampling Trees tool, to infer manuscript-transmission stemmata. The model incorporates: intrinsic "root reading priors" (probability that a given variant reading is the original authorial one), custom irreversible substitution models with rate parameters for specific scribal-error types (e.g., Byzantine assimilation, harmonization), multiple clock models (strict / relaxed / random-local, to allow different manuscript lineages to accumulate copying errors at different rates), manuscript-date constraints on tree topology, and Birth-Death-Skyline tree priors chosen specifically to avoid biasing the inferred tree toward asymmetric shapes. MCMC sampling produces a posterior *distribution* over stemma topologies rather than one best tree. Tested on the Epistle to the Ephesians, it recovered established manuscript groupings (Western Greek-Latin, Byzantine, Coptic clusters) consistently across clock-model choices — [Using Bayesian phylogenetics to infer manuscript transmission history](https://academic.oup.com/dsh/article/39/1/258/7477852)
- That paper explicitly scopes itself to manuscript-transmission-history reconstruction and does **not** discuss applicability to allusion or textual-reuse detection between distinct texts — confirmed by direct inspection of its content, not merely absence of a hit.

### Inferences
- The stemmatology toolchain is built around a premise that does not hold for the project's task: it assumes the compared witnesses are *copies of the same underlying text* with a small number of localized, classifiable variant types (scribal errors, harmonizations) connected by a tree (each copy has exactly one/few parents). The project's task — a 19th-century novel paraphrasing/alluding to a Bible it does not textually descend from in the manuscript sense — is a many-to-many, non-treelike, heavily-transformed-content relationship, which is structurally closer to a citation/allusion network (Key Question 3) than to a stemma. The transferable idea, if any, is *not* the phylogenetic tree-inference machinery itself, but the general discipline of (a) explicitly modeling different types of textual transformation with different priors/costs (the substitution-model idea — e.g., a "high-probability" transformation type like synonym substitution vs. a "low-probability" one like unrelated coincidental overlap) and (b) reporting a *distribution* over hypotheses (posterior probability) rather than a single point score — both of which could inspire a more principled probabilistic combination of the project's three existing signals than a single fitted logistic-regression weight vector, but this is a methodological inspiration, not a directly reusable tool.
- Given the scale and nature mismatch, stemmatology should be treated as a *low-priority, indirect* methodological neighbor for this project rather than a source of directly applicable graph-construction or scoring techniques.

### Gaps
- No source was found that explicitly bridges stemmatology/phylogenetic textual-criticism methods to allusion or intertextual-citation detection (as opposed to manuscript-copy relationships); this connection, if it exists in the literature, was not surfaced by the queries run, and should be considered an open question rather than a ruled-out possibility.

## Key Question 6: What would be required to adapt the existing unrelated GNN (hybrid GATv2 + full self-attention, multi-edge-type text-as-graph, trained for regression on 40k-200k documents) to this allusion-detection task? Is there established methodology for transferring a GNN from a large regression task to a small-label pairwise-similarity task?

### Takeaway
There is well-established methodology for exactly this kind of transfer — freeze the pretrained encoder as a fixed feature extractor and train only a small new head on top, which is documented to reduce overfitting and be far more compute-efficient than full fine-tuning — but a frank assessment of the scale, domain, and task mismatch (regression on full documents at 40k-200k-example scale vs. a handful of short sentence-level dependency graphs with ~16-30 labels) suggests that reusing this specific GNN's *trained weights* is unlikely to be a good use of effort; reusing its *architectural ideas* (a GATv2-then-attention hybrid encoder, applied fresh to dependency subgraphs) is far more defensible than reusing the trained model itself.

### Cited Findings
- Standard practice for transferring a pretrained GNN to a new downstream task distinguishes "freezing mode" (pretrained encoder treated as a static feature extractor; only a task-specific head/classifier is trained) from "full fine-tuning mode" (all weights updated); freezing is documented to make downstream training 10-30x faster (no gradients computed for the encoder), to reduce overfitting specifically "in small datasets by reusing robust pre-trained features," and to give stronger out-of-distribution performance — all properties directly relevant to a ~16-30-label target task — [Frozen encoders in GNN transfer learning](https://medium.com/@utsavsharma1990/frozen-encoders-foundations-applications-and-advanced-techniques-5b17688dd09a)
- Formal treatments of GNN transferability (e.g., Ego-Graph Information maximization, EGI) study exactly the question of when and how a GNN's structural encoding learned on one graph/task transfers to another, providing a theoretical basis for the frozen-encoder approach in graph settings specifically (as opposed to just being borrowed from the vision/NLP transfer-learning literature) — [Transfer Learning of GNNs with Ego-Graph Information Maximization (EGI)](https://proceedings.neurips.cc/paper_files/paper/2021/file/0dd6049f5fa537d41753be6d37859430-Paper.pdf)
- Self-supervised contrastive GNN pretraining (GCC) explicitly frames its value proposition as: pretrain once (no labels), then either freeze-and-add-a-head or lightly fine-tune with conservative learning rates on the downstream labeled set, with the biggest benefit precisely when downstream labels are scarce — [GCC: Graph Contrastive Coding for GNN Pre-Training](https://arxiv.org/pdf/2006.09963)
- No source was found describing transfer of a GNN trained for *document-level regression* (predicting a continuous engagement/quality score from a whole-document graph) to a *short-span pairwise similarity/classification* task; all frozen-encoder/transfer evidence gathered concerns same-domain transfer (e.g., graph classification benchmark to graph classification benchmark, or node classification to node classification), not a cross-task, cross-scale jump of the kind being asked about here.

### Inferences
- The existing engagement-prediction GNN operates on a different unit of analysis (whole documents, tens of thousands to hundreds of thousands of nodes'-worth of training signal, four to five edge types including a virtual fully-connected node and LLM-derived discourse edges between sentences) than the allusion-detection task needs (short spans — a sentence or short paragraph vs. a single Bible verse — with a small, specific edge type: dependency relations, possibly augmented with shared-lemma edges). Directly loading its trained weights as a frozen encoder is unlikely to help much, for three compounding reasons that should be stated plainly: (1) its training objective (predicting reader engagement) has no obvious relationship to syntactic/lexical borrowing — there is no reason to expect its learned node embeddings to separate "these two spans share a citation relationship" from "these two spans do not," since it was never asked to make that distinction; (2) its input scale (whole documents, with pooling to a document-level vector before the regression heads) is architecturally mismatched to a task that needs *fine-grained, sub-document, pairwise* comparison between a short target span and a short source span — pooling to a single document vector would likely destroy exactly the localized structural information the allusion-detection task needs; (3) the domains differ sharply (general web/publication text vs. a 19th-century Russian novel and a Church-Slavonic-registered Bible translation), and GNN structural encoders are known (per EGI-style transferability research generally) to transfer best when source and target graphs share structural/domain properties, which is not clearly the case here.
- What *is* plausibly reusable is the architectural pattern, not the weights: a small GATv2-message-passing-then-self-attention hybrid encoder is a reasonable, modern, VRAM-modest architecture choice to apply *freshly* (randomly initialized, or contrastively pretrained per Key Question 2) to short dependency (sub)graphs for the allusion task. This reframes "adapt the existing GNN" as "reuse the existing GNN's *architectural recipe*, retrained/pretrained from scratch on the much smaller and differently-shaped allusion-detection graphs" — which is a legitimate and modest-hardware-feasible undertaking, clearly distinct from (and more honest than) claiming the existing trained model itself can be repurposed.
- Using the existing GNN's *output embeddings* as one more feature in the existing ensemble (an idea floated in the assignment) is the least risky reuse mode if any reuse is attempted at all — it costs only inference time, does not require retraining or freezing/unfreezing decisions, and the logistic-regression combination step already in place would empirically down-weight this feature (as it already did for the syntax-edge signal, fitting it to near-zero) if it turns out to be uninformative, at zero risk to the rest of the pipeline. But given point (1) above, expectations for this specific feature should be low.

### Gaps
- No direct evidence (positive or negative) was found on whether frozen embeddings from a document-level engagement-prediction GNN carry any signal useful for a sentence/verse-level textual-borrowing task; this is an empirically answerable but currently untested question specific to this project's own trained model, and the honest recommendation is to treat it as a cheap, optional experiment (extract embeddings, add as a fourth logistic-regression feature, check via the existing LOTO-CV protocol whether its fitted weight is distinguishable from zero) rather than to invest in deeper architectural surgery (fine-tuning, partial unfreezing) without first checking whether the frozen embeddings help at all.
- No source discussed the specific sub-case of transferring a GNN across a large difference in graph *size* (document-level graphs likely containing hundreds to thousands of token-nodes vs. dependency graphs of a handful to ~30 nodes per verse/sentence); pooling and normalization behavior of GNNs is known in general to be sensitive to graph size distribution shift, but no source quantified this for a shift of this magnitude, so this remains a plausible additional obstacle rather than a documented one.
